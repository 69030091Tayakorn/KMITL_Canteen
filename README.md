# KMITL Canteen

Python Desktop App สำหรับสั่งอาหารล่วงหน้า พัฒนาด้วย CustomTkinter และ SQLite

## วิธีทำงานที่ตกลงกัน (14 ตุลาคม 2026)

- สร้าง/แก้ตาราง และเพิ่มโรงอาหาร ร้าน เมนู ราคา ตัวเลือก สถานะขาย ผ่าน **DB Browser for SQLite**
- Python ใน VS Code ใช้เชื่อมต่อ อ่านข้อมูล แสดงหน้าจอ และบันทึกออเดอร์ที่ลูกค้าสั่ง
- แอปไม่สร้างตาราง ไม่เติมข้อมูลตัวอย่าง และไม่มีหน้าจัดการเมนูอีกต่อไป
- ข้อมูลร้านและเมนูปัจจุบันเป็นข้อมูลตัวอย่าง ไม่ใช่ผลสำรวจครบมหาวิทยาลัย

## ฐานข้อมูล

เปิด `Database SQLite/canteen.db` ใน DB Browser ข้อมูลเดิมยังอยู่ ไม่ต้องสร้างใหม่

| ตาราง | ข้อมูล |
|---|---|
| canteens | โรงอาหาร |
| shops | ร้าน เชื่อมโรงอาหารด้วย canteen_id |
| menu_items | เมนู ราคา สถานะขาย เชื่อมร้านด้วย shop_id |
| menu_options | กลุ่มตัวเลือกและราคาเพิ่มของร้าน |
| orders | ผู้รับ ร้าน วันเวลารับ และสถานะออเดอร์ |
| order_items | อาหาร จำนวน ราคาและตัวเลือกขณะสั่ง |

ตาราง `app_settings` ที่อาจมีในไฟล์เดิมเป็นของขั้นนำเข้าข้อมูลรุ่นก่อน แอปไม่ได้ใช้แล้ว เก็บไว้โดยไม่ลบข้อมูลเดิม

## การตั้งค่าบนเครื่องใหม่เท่านั้น

1. สร้าง `Database SQLite/canteen.db` ด้วย DB Browser
2. เปิด `schema.sql` ในแท็บ Execute SQL แล้วรันเพื่อสร้างตาราง
3. ถ้าต้องการข้อมูลตัวอย่าง ให้รัน `sample_data.sql` เฉพาะฐานข้อมูลใหม่ที่ยังไม่มีข้อมูล
4. กด Write Changes

ไฟล์ SQL เป็นคำสั่งสำหรับเปิดใน DB Browser ไม่ใช่สิ่งที่แอปรันอัตโนมัติ ไฟล์ฐานข้อมูลจริงและ QR ส่วนตัวไม่รวมใน Git

## วิธีแก้ข้อมูล

ดูวิธีและคำสั่งใน `Database SQLite/README.md` หลังแก้ให้กด Write Changes แล้วกลับเข้าโรงอาหาร/เมนูใหม่ หรือเปิดแอปใหม่

## สถานะระบบ

มีปุ่ม **ฝั่งร้านค้า (สาธิต)** ให้เลือกโรงอาหาร/ร้าน ดูรายละเอียดอาหาร ยอด ผู้รับ และเปลี่ยนสถานะ:
`awaiting_payment_review` → `paid` → `preparing` → `ready` → `completed`

ร้านสามารถตั้ง `payment_rejected` เมื่อยังตรวจรับเงินไม่ได้ และนำกลับมาตรวจใหม่ได้ การยืนยันเงินมีคำถามยืนยัน แต่ไม่ได้เชื่อมธนาคารหรือมีสลิปในระบบ ออเดอร์เก่า `pending` แสดงเพื่อดูข้อมูลเท่านั้น ไม่มีการเปลี่ยนตารางหรือเติมข้อมูลอัตโนมัติ

`Backend/shop_orders.py` อ่านออเดอร์และตรวจการเปลี่ยนสถานะ; `Frontend/shop_orders_page.py` แสดงหน้าร้าน การเลือกร้านยังไม่มีล็อกอิน จึงเป็นการสาธิตในเครื่องเดียว ไม่ใช่ระบบควบคุมสิทธิ์สำหรับใช้งานจริง

เลือกโรงอาหาร ร้าน เมนู ตัวเลือก ใส่ตะกร้าแยกร้าน และกรอกผู้รับพร้อมเลือกวันเวลารับได้ แสดง QR สำหรับทดสอบและบันทึกการแจ้งชำระเป็น `awaiting_payment_review` ได้ ยังไม่ได้ตรวจเงินเข้า แนบสลิป ส่งออเดอร์ไปเครื่องร้านค้า หรือจำกัดสิทธิ์ด้วยล็อกอิน

ราคาออเดอร์เก่าไม่เปลี่ยนตามราคาเมนูใหม่ รายการในตะกร้าที่ราคาเปลี่ยนหรืออาหารหมดต้องเลือกใหม่ก่อนยืนยัน

## รันแอป

```powershell
python -m pip install -r requirements.txt
python main.py
```

## ไฟล์หลัก

- `Backend/database.py`: เชื่อมฐานข้อมูลเดิมและเปิดตรวจ Foreign Key
- `Backend/catalog.py`: อ่านข้อมูลร้าน/เมนูและตรวจข้อมูลในตะกร้า
- `Backend/orders.py`: บันทึกออเดอร์และอาหารใน transaction เดียวกัน
- `Backend/menu.py`: คำนวณราคาจากข้อมูลที่อ่านมา
- `Frontend/app.py`: หน้าหลักและตะกร้า
- `Frontend/menu_page.py`: หน้าเลือกเมนู
- `Frontend/checkout_page.py`: ข้อมูลผู้รับและตรวจรายการ
- `Frontend/payment_page.py`: QR สำหรับแจ้งชำระทดสอบ

ทดสอบด้วย `python -m unittest discover -s tests -v` โดยไม่แก้ฐานข้อมูลจริง
